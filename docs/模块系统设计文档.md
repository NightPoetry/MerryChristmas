# 模块系统设计文档

## 一、核心设计理念

模块系统（Modules System）是一个基于面向对象设计的实体管理系统，通过简洁的语法定义实体，实现属性监控、事件触发和单例管理。系统采用文件夹作为包名的命名空间机制，支持实体的单例使用和动态招募，同时通过代理实现属性的全面监控。

## 二、核心语法规则

### 2.1 模块与实体命名规则

- **模块结构**：`modules/文件夹名/实体文件名.entity`
- **调用方式**：
  - 普通实体：`modules.文件夹名.实体文件名`
  - 同名实体简化：若文件夹下存在与文件夹同名的实体文件（如`modules/user/user.entity`），可直接使用`modules.user`调用

### 2.2 实体定义语法

```
实体名{
    数据类型 属性名
    数据类型 属性名
    
    when(条件表达式){
        // 条件满足时执行的JS操作
    }
    
    judge 函数名{
        // 判断逻辑，仅允许属性计算和调用其他judge函数
    }
    
    返回类型 函数名(参数类型 参数名, 参数类型 参数名){
        // 函数实现
        return 返回值;
    }
}
```

#### 示例：

```
User{
    number a
    number b
    
    when(a > b){
        console.log("a大于b");
    }
    
    judge isActive(){
        return this.a > 0 && this.b > 0;
    }
    
    number sum(number x, number y){
        return x + y;
    }
}
```

## 三、数据类型系统

### 3.1 基本数据类型

参考数据库设计文档，支持以下数据类型：

| 类型 | 描述 | 示例 |
|------|------|------|
| number | 数值类型，可存储整数或小数 | `number a` |
| number[整数位.小数位] | 定点小数，支持精确精度 | `number[3.4] balance` |
| str[长度] | 字符串类型，指定最大长度 | `str[50] name` |
| datetime | 日期时间类型 | `datetime createTime` |
| bool | 布尔类型 | `bool isActive` |

### 3.2 非基本数据类型

| 类型 | 描述 | 示例 |
|------|------|------|
| 实体名 | 1-n关联，存储目标实体ID | `Warehouse myWarehouse` |
| List[实体名] | n-n关联，由专属关联表维护 | `List[Tag] tags` |

## 四、实体执行器

### 4.1 位置与作用

- **位置**：实体执行器位于`core`目录下，属于核心通用内容
- **作用**：解析并执行实体脚本，管理实体的生命周期和状态

### 4.2 执行流程

1. 解析实体文件，提取属性、方法、judge函数和when语句
2. 创建实体的代理对象，实现属性监控
3. 注册事件监听器，处理when语句触发
4. 管理实体的单例实例
5. 处理实体的招募（recruit）操作

## 五、核心特性

### 5.1 单例模式

- **默认行为**：实体默认采用单例模式，全局唯一实例
- **调用方式**：`modules.user.User.xxx`

### 5.2 招募机制（Recruit）

- **目的**：避免与面向对象的`new`关键字混淆，明确表示创建新的实体实例
- **语义**：重新招揽一个实体，获得初始化状态的实体实例
- **使用场景**：需要多个独立实体实例时使用

### 5.3 属性监控与代理

- **实现方式**：使用JavaScript的Proxy语法实现
- **功能**：对实体的所有属性进行全面监控，捕获属性的读取和写入操作
- **应用**：用于触发when语句和属性变化事件

### 5.4 When语句（事件触发机制）

- **本质**：一种基于属性变化的事件触发机制
- **触发条件**：当涉及的属性发生变化时自动触发
- **特殊事件**：
  - `before funcs`：函数执行前触发
  - `after funcs`：函数执行后触发

#### 示例：

```
when(before funcs && a > 3){
    // 函数执行前，且属性a大于3时执行
    this.b += 1;
}
```

### 5.5 Judge函数

- **定义**：用于封装判断逻辑的特殊函数
- **限制**：
  - 仅允许执行其他judge函数
  - 仅允许进行属性计算
  - 禁止任何属性赋值操作（会直接报错）
- **设计原则**：保证可重复执行不变性，避免反复执行时产生无效写入

#### 示例：

```
judge isEligible(){
    return this.age >= 18 && this.score > 60;
}
```

### 5.6 普通函数

- **语法**：类似C语言，但使用自定义数据类型
- **返回值**：必须指定返回值类型
- **参数**：必须指定参数类型和参数名

#### 示例：

```
number add(number a, number b){
    return a + b;
}

str concat(str a, str b){
    return a + b;
}
```

## 六、使用场景

### 6.1 路由中的实体调用

```javascript
// 使用单例实体
modules.user.User.updateProfile();

// 招募新实体实例
const newUser = modules.user.User.recruit();
newUser.init("test", 20);
```

### 6.2 事件驱动的业务逻辑

```
User{
    number balance
    str status
    
    when(balance < 0){
        this.status = "overdrawn";
        notifyUser("账户余额不足");
    }
    
    when(after withdraw && balance > 0){
        logTransaction("取款成功");
    }
}
```

### 6.3 复杂条件判断封装

```
User{
    number age
    number score
    bool isActive
    
    judge isQualified(){
        return this.isActive && this.age >= 18 && this.score > 60;
    }
    
    when(isQualified()){
        grantAccess();
    }
}
```

## 七、核心优势

1. **简洁的语法**：采用类似面向对象的简洁语法，降低学习成本
2. **强大的事件机制**：基于属性变化的when语句，实现灵活的事件驱动编程
3. **安全的判断逻辑**：judge函数的限制确保了判断逻辑的可靠性和性能
4. **清晰的命名空间**：文件夹作为包名的机制，实现了良好的模块隔离
5. **灵活的实例管理**：同时支持单例模式和招募机制，适应不同场景需求
6. **全面的属性监控**：通过Proxy实现的属性监控，为事件触发提供可靠基础
7. **与数据库设计结合**：复用数据库设计的data types，保持系统一致性

## 八、与其他系统的关系

### 8.1 与数据库系统的关系

- **数据类型复用**：实体系统的数据类型参考数据库设计文档
- **实体映射**：实体可映射到数据库表，实现对象-关系映射
- **持久化支持**：实体的属性变化可自动同步到数据库

### 8.2 与路由系统的关系

- **模块调用**：路由中可直接调用实体的方法
- **业务逻辑封装**：实体封装业务逻辑，路由专注于请求处理
- **状态管理**：实体可管理业务状态，支持复杂的业务流程

## 九、未来扩展方向

1. **类型系统增强**：支持更多复杂数据类型和自定义类型
2. **事件机制优化**：支持事件优先级和异步事件处理
3. **实体间通信**：支持实体间的消息传递机制
4. **持久化增强**：支持更多数据库类型和高级查询
5. **性能优化**：优化代理对象的性能，支持大规模实体管理
6. **调试工具**：提供实体状态调试和事件触发跟踪工具

## 十、总结

模块系统是一个设计简洁、功能强大的实体管理系统，通过面向对象的语法、属性监控、事件触发和灵活的实例管理，为应用程序提供了可靠的业务逻辑封装机制。系统的设计理念注重简洁性、灵活性和性能，适合构建复杂的业务应用程序。
