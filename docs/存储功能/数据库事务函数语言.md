# 数据库事务函数设计
## 一、文档概述
### 1.1 设计目标
- 一体化特性：融合「数据库事务原子性（ACID）」与「外部可调用函数」能力，无需额外配置即可实现复杂业务的一致性管控与外部触发；
- 类型精准性：通过定点小数标识避免精度丢失，统一类型定义语法，适配数据库对数据精度的严格要求；
- 语法兼容性：无缝衔接现有数据库操作语言（实体CRUD、关联处理）与结构描述语言，复用已有变量规则、执行策略，降低迁移成本；
- 自然语义性：判断、循环、参数默认值等语法贴合自然英语表达习惯，搭配缩进式语法，提升可读性与易用性；
- 解析轻量化：移除语句块大括号，释放大括号语义使其专用于变量标识；解放小括号，使其用于参数默认值定义（仅适用于真实数据类型），明确`list`伪类型无默认值，简化执行器解析逻辑；
- 返回规范性：严格限定返回值为已有类型/变量，禁用临时`{}`构造返回结构，依托实体懒加载自动全面加载，保证返回结构的一致性与完整性；
- 灵活易用性：变量引用通过大括号统一标识，真实类型参数默认值支持小括号+自然语言双表述，语法直观无歧义；
- 低改造成本：核心设计灵感源于对现有执行器逻辑的最小化扩展，无需重构底层架构即可实现功能落地；
- 数据优先性：默认采用最高事务隔离级别，优先保障数据准确性与一致性，规避脏读、不可重复读、幻读等问题。

### 1.2 核心定位
作为现有数据库语言体系的扩展层，专门用于描述包含多步数据库操作的原子性事务。既可以内部关联实体关系、复用数据操作逻辑，也能作为独立函数被外部调用，解决复杂业务场景（如订单支付、资金转账、商品购买）中的数据一致性问题，同时通过规范的返回值规则保证外部调用的数据可用性。

## 二、核心语法规则
### 2.1 函数定义基础格式（缩进式语法，无语句块大括号）
```
[注解] 函数名(参数列表):
    数据库操作语句1
    数据库操作语句2
    ...
    [return 已有变量/已有类型实例]
```
- 注解（可选）：用于配置事务属性，如隔离级别、传播行为，格式为`@注解名(参数)`；
- 函数名：采用帕斯卡命名法（如`GetUserProfile`、`PurchaseGoods`），需唯一标识事务逻辑；
- 冒号+缩进：函数头末尾用冒号`:`标识语句块开始，后续所有函数体内语句需统一缩进（推荐Tab缩进，兼容2/4空格缩进），缩进层级对应语句块作用域；
- 参数列表：支持多参数定义，格式为「类型:参数名 [约束属性] [默认值定义]」，参数间用逗号分隔；**仅真实基础类型支持小括号默认值定义，`list`伪类型不支持默认值**；
- 函数体：包含1~N条数据库操作语句（遵循现有数据库操作语言语法），所有操作构成一个原子事务，通过缩进界定作用域，无需大括号；
- 返回语句（可选）：
  1.  核心规则：仅允许返回「已有变量」或「已有类型实例」，**禁用临时`{}`构造返回结构**（大括号已专用于变量标识，避免语义冲突）；
  2.  已有变量：包括函数参数、内部定义变量、`Get`操作生成的实体变量（如`targetUser`、`newOrder`）、`list`类型批量变量（如`userOrders`）；
  3.  已有类型实例：指预先定义的实体类型（如`User`、`Order`），返回时触发该类型的连锁懒加载，自动补全所有关联结构与字段内容；
  4.  缩进要求：`return`语句需与函数体内其他语句保持相同缩进层级。

### 2.2 事务特性约定
- 原子性：函数体内所有操作要么全部提交成功，要么全部回滚，默认自动开启事务，无需显式声明；
- 隔离级别：支持4种标准隔离级别，**默认`SERIALIZABLE`（最高级别）**，优先保证数据准确性，规避脏读、不可重复读、幻读所有问题；支持配置其他级别，示例：`@Isolation(REPEATABLE_READ) PurchaseGoods(...)`、`@Isolation(READ_COMMITTED) GetUserProfile(...)`；
- 传播行为：默认`REQUIRED`（无事务则新建，有事务则加入），支持`REQUIRES_NEW`（强制新建独立事务），配置示例：`@Propagation(REQUIRES_NEW) TransferFund(...)`；
- 自动提交：事务函数执行完成后自动提交，异常（含手动抛出）时自动回滚，支持自然语义的异常捕获与回滚逻辑；
- 懒加载特性：返回实体类型/变量时，自动触发「连锁获取/全面加载」，补全该实体所有关联数据与字段，无需手动查询关联信息。

### 2.3 核心语法变更说明
1.  移除所有语句块（函数体、判断、循环、异常处理）的`{}`，通过「冒号+缩进」界定作用域，风格类似Python；
2.  释放`{}`语义，使其唯一用于变量标识，实现变量引用的统一化，简化解析逻辑；
3.  解放小括号`()`，使其专用于**真实基础类型**的参数默认值定义，替代原有`? =`的写法，更贴合自然英语表达；
4.  明确`list`伪类型特性：`list`仅作为函数内数据结构描述（用于参数传递、循环遍历），非数据库真实存储类型，**不支持默认值定义**，必须作为必选参数传入；
5.  新增返回值严格规则：
    - 禁止使用临时`{key: value}`构造返回结构，消除与变量标识`{变量名}`的语义冲突；
    - 仅允许返回已有变量（参数、内部变量、实体变量、list变量）或已有类型实例；
    - 实体类型/变量返回时，触发连锁懒加载，自动全面加载该结构所需的所有字段与关联数据，保证返回数据的完整性；
6.  缩进规则：
    - 基础缩进：函数体内语句相对于函数头缩进1级（Tab/2/4空格）；
    - 嵌套缩进：判断、循环、异常处理等嵌套语句块，相对于外层语句再缩进1级，层级清晰无歧义；
    - 缩进兼容：执行器自动识别缩进层级，无需严格限制空格数，仅需保证同一语句块内缩进一致。

## 三、数据类型系统
### 3.1 基本类型（真实类型，支持默认值）
| 类型标识       | 说明                          | 示例                          | 对应数据库类型       | 设计目的                  | 默认值支持情况       | 作为返回值说明              |
|----------------|-------------------------------|-------------------------------|----------------------|---------------------------|----------------------|-----------------------------|
| `number`       | 整数类型（默认64位）          | `number:user_id`、`number:age` | BIGINT               | 适配常规整数存储需求      | 支持（小括号+自然语言） | 可直接返回单个number变量（如`return {user_id}`） |
| `number[P.S]`  | 定点小数（P总位数，S小数位数） | `number[5.2]:price`（999.99） | DECIMAL(P,S)         | 避免浮点数精度丢失，满足金额、比例等精准场景 | 支持（小括号+自然语言） | 可直接返回单个定点小数变量（如`return {final_total}`） |
| `str[L]`       | 字符串（L为最大长度）         | `str[100]:username`           | VARCHAR(L)           | 统一字符串长度约束语法    | 支持（小括号+自然语言） | 可直接返回单个字符串变量（如`return {username}`） |
| `datetime`     | 日期时间类型                  | `datetime:create_time`        | DATETIME             | 适配时间类数据存储        | 支持（小括号+自然语言） | 可直接返回单个日期时间变量（如`return {create_time}`） |
| `bool`         | 布尔类型                      | `bool:is_active`              | BOOLEAN              | 简化布尔值存储表示        | 支持（小括号+自然语言） | 可直接返回单个布尔变量（如`return {is_vip}`） |

### 3.2 复合类型（`list`伪类型，不支持默认值）
- 定义规则：通过`list[基础类型]`表示同类型数组，`list`仅作为函数内的结构描述（伪类型），不对应数据库底层存储类型，仅用于参数传递、循环遍历等场景；
- 嵌套支持：允许多层嵌套，内层类型需为基本类型或已定义的嵌套列表，支持复杂数据结构传递；
- 示例：
  - `list[number]`：整数列表（如商品ID列表`[101, 102, 103]`）
  - `list[str[50]]`：字符串列表（如标签名称列表`["电子", "数码"]`）
  - `list[number[3.2]]`：定点小数列表（如折扣比例列表`[0.9, 0.85]`）
  - `list[list[number]]`：二维整数列表（如批量订单ID列表`[[1001, 1002], [1003, 1004]]`）
  - `list[User]`：用户实体列表（批量查询返回的用户集合）
- 关键约束：`list`作为伪类型，**不支持默认值定义**，必须作为必选参数传入；
- 作为返回值说明：可直接返回list类型变量（如`return {userOrders}`），返回时若包含实体类型，将触发列表内每个实体的连锁懒加载；
- 设计说明：`list`不作为独立数据库类型，仅为函数内操作提供便捷语法，避免占用数组原生表示方式，同时明确其伪类型属性，消除默认值配置的歧义。

### 3.3 实体类型（已有自定义类型，支持连锁懒加载）
- 定义规则：预先通过数据库结构描述语言定义的业务实体类型（如`User`、`Order`、`Goods`、`Coupon`），包含字段定义与关联关系配置；
- 关联配置：支持一对一、一对多、多对多关联（如`User`关联`Order`（一对多）、`Order`关联`Goods`（多对多））；
- 作为返回值核心特性：
  1.  直接返回实体变量：如`return {targetUser}`、`return {newOrder}`，触发该实体的连锁懒加载；
  2.  直接返回实体类型实例：如`return User`（需提前通过`Get`操作获取默认实例），自动补全实例所有字段与关联数据；
  3.  连锁懒加载逻辑：返回实体时，自动遍历该实体的所有关联配置，递归查询关联实体数据，补全完整数据结构，无需手动执行关联查询；
  4.  示例：返回`{newOrder}`时，自动加载关联的`User`（下单用户）、`OrderItem`（订单项）、`Goods`（商品）、`Coupon`（优惠券）等所有关联数据。

## 四、参数与变量规则（小括号用于真实类型默认值，list伪类型无默认值）
### 4.1 参数规则（核心：真实类型默认值+list伪类型必选约束）
#### 4.1.1 必选参数
- 分类1：真实基础类型必选参数（无默认值，需外部传入）
  - 格式：「类型:参数名 [约束属性]」
  - 示例：`number:user_id`、`str[50]:email [not null unique]`、`datetime:query_start`
- 分类2：`list`伪类型必选参数（唯一类型，无默认值，强制外部传入）
  - 格式：「list[基础类型/实体类型]:参数名 [约束属性]」
  - 示例：`list[number]:goods_ids [not null]`、`list[str[20]]:tag_names`、`list[User]:valid_users`
  - 约束：`list`参数必须指定`[not null]`（可选但推荐），不可添加任何默认值定义，执行器会校验并拒绝`list`参数的默认值配置。

#### 4.1.2 可选参数（仅真实基础类型支持，list伪类型无此分类）
##### 写法1：小括号直接指定默认值（简洁直观，推荐）
- 格式：「类型:参数名 (默认值) [约束属性]」
- 说明：小括号内填写默认值，类型需与参数类型匹配，无需额外关键字，解析效率更高，仅适用于真实基础类型；
- 示例：
  - `number[3.2]:discount (0.9)`：折扣参数默认值0.9（定点小数类型）
  - `str[20]:coupon_code ("")`：优惠券码默认值为空字符串（字符串类型）
  - `bool:is_vip (false)`：是否VIP默认值为false（布尔类型）
  - `datetime:query_time (datetime.now())`：查询时间默认值为当前时间（日期时间类型）

##### 写法2：自然语言表述（贴合英语语法，可读性更强）
- 格式1：「类型:参数名 (default is 默认值) [约束属性]」
- 格式2：「类型:参数名 (with default value 默认值) [约束属性]」（进阶表述，兼容扩展）
- 说明：通过自然英语短语声明默认值，更符合自然语义习惯，执行器自动解析小括号内的`default is`关键字提取默认值，仅适用于真实基础类型；
- 示例：
  - `number[3.2]:discount (default is 0.9)`：等价于`number[3.2]:discount (0.9)`
  - `str[20]:coupon_code (default is "")`：等价于`str[20]:coupon_code ("")`
  - `bool:is_vip (with default value false)`：等价于`bool:is_vip (false)`
  - `datetime:query_time (default is datetime.min())`：默认值为最小日期时间

##### 两种写法兼容说明
- 语义等价：两种写法执行效果完全一致，执行器自动识别并统一转换为底层默认值配置；
- 灵活切换：可根据团队习惯选择写法，支持在同一函数参数列表中混合使用；
- 约束兼容：默认值定义可与`[not null]`、`[unique]`、`[max:数值]`等约束属性搭配使用，约束优先级高于默认值；
- 适用范围：仅覆盖`number`、`str[L]`、`datetime`、`bool`等真实基础类型，`list`伪类型与实体类型不支持此两种写法。

#### 4.1.3 参数约束
- 支持属性：`[not null]`（非空）、`[unique]`（唯一）、`[max:数值]`（最大值）、`[min:数值]`（最小值）、`[length:数值]`（字符串长度，仅适用于`str[L]`）；
- 示例：
  - 真实类型带约束+默认值：`number:age (18) [min:0, max:120]`（年龄默认18，最小值0，最大值120）
  - list伪类型带约束：`list[number]:goods_ids [not null]`（商品ID列表非空，无默认值）
- 作用域：所有参数在整个事务函数内有效，可通过大括号标识引用，`list`参数的元素需通过循环遍历获取，实体类型参数可直接引用其字段。

### 4.2 变量核心规则（大括号唯一标识，简化解析）
#### 4.2.1 核心设计：大括号专用于变量引用
- 设计目的：释放大括号的语句块语义，使其唯一承担变量标识功能，消除语法歧义，大幅降低执行器解析复杂度，同时为返回值禁用临时`{}`提供语法支撑；
- 核心要求：所有变量（参数、内部变量、实体字段）引用必须用`{变量名}`格式标识，无兼容写法，语法统一直观；
- 解析优势：执行器无需区分大括号是语句块、临时结构还是变量标识，仅需识别`{xxx}`格式即可判定为变量引用，简化解析逻辑，提升解析效率。

#### 4.2.2 变量引用示例
- 真实类型参数（含默认值）引用：`Get a user by id of {user_id} as targetUser`、`Set {final_discount} = {discount} * (1 - {coupon_discount})`；
- list伪类型参数引用：`Get [goods]s where id in {goods_ids} as purchasedGoods`、`For Each item in {orderItems} Do:`；
- list参数元素引用：`Set {total} = {total} + {item.price} * {item.quantity}`、`Update a goods by id of {good.id} to set stock = {good.stock} - 1`；
- 实体变量及字段引用：`If {sender.balance} is less than {amount}`、`Update the targetUser to set username to {new_name}`；
- 内部变量引用：`Update the order to set total to {total}`、`Set {final_total} = {total} * {discount}`；
- 字面量区分：变量`{paid}`与字面量`'paid'`清晰区分，无重名风险，示例：`Set status to {paid}`（变量）、`Set status to 'paid'`（固定值）。

#### 4.2.3 内部变量规则（复用现有设计，适配返回值规则）
- 变量生成：
  1.  `Get`操作未显式命名时自动生成默认变量（如`Get a user...`生成`user`变量，引用为`{user}`）；
  2.  `as`关键字显式命名变量（如`Get a user as targetUser`，引用为`{targetUser}`），该变量可直接作为返回值；
- 作用域：内部变量仅在当前事务函数内有效，事务结束后自动销毁，不与其他函数变量冲突，通过缩进界定嵌套语句块内的变量可见性；
- 默认变量指向：`the + 实体名`仍指向最后一次`Get`的该类实体默认变量（如`the user`指向最后获取的用户实体，引用为`{the user.balance}`），可直接返回`{the user}`；
- 变量赋值：通过`Set {变量名} = 表达式`格式赋值，示例：`Set {total} = 0`、`Set {discount} = 0.8`，赋值后的变量可直接作为返回值；
- 实体变量特性：内部生成的实体变量（如`newOrder`、`purchasedGoods`）包含基础字段，返回时自动触发连锁懒加载，补全所有关联数据；
- list类型内部变量：函数内通过查询生成的批量实体集合（如`userOrders`）本质为`list`类型，可直接作为返回值，返回时触发批量实体的连锁懒加载。

### 4.3 返回值专属规则（禁用临时{}，仅返回已有变量/类型）
#### 4.3.1 允许的返回值类型及示例
| 返回值类别         | 具体说明                                                                 | 合法示例                                  | 适用场景                                  |
|--------------------|--------------------------------------------------------------------------|-------------------------------------------|-------------------------------------------|
| 单个真实类型变量   | 函数参数或内部赋值的基础类型变量，直接返回变量值                          | `return {user_id}`、`return {final_total}` | 返回单个ID、金额、状态等值类型数据        |
| 单个实体类型变量   | `Get`操作生成的实体变量，返回时触发连锁懒加载，补全所有关联数据            | `return {targetUser}`、`return {newOrder}` | 返回完整的业务实体（含关联数据）          |
| list类型变量       | 批量实体集合或基础类型列表，返回时触发列表内每个实体的连锁懒加载          | `return {userOrders}`、`return {goods_ids}` | 返回批量数据（如订单列表、商品ID列表）    |
| 实体类型实例       | 预先定义的实体类型，返回时自动加载默认实例的完整数据（含关联）            | `return User`、`return Order`             | 返回某类实体的默认完整结构                |
| 逻辑表达式变量     | 基于已有变量的逻辑计算结果，需先通过`Set`赋值为内部变量，再返回该变量      | `Set {is_success} = {final_total} > 0` <br> `return {is_success}` | 返回逻辑判断结果                          |

#### 4.3.2 严格禁止的返回行为
1.  禁止使用临时`{}`构造键值对结构：如`return {success: true, order_id: {newOrder.order_id}}`（违反大括号专属变量标识的语义，执行器直接抛出语法错误）；
2.  禁止返回未定义的临时值：如`return 0.9`、`return "success"`（需先通过`Set {default_discount} = 0.9`赋值，再返回`{default_discount}`）；
3.  禁止返回混合临时结构与变量的内容：如`return {user: {targetUser}, total: {final_total}}`（需将混合结构封装为实体类型，再返回实体变量）；
4.  禁止返回未初始化的变量：如未执行`Get`操作直接返回`{the user}`（执行器校验变量是否已初始化，未初始化则抛出异常）。

#### 4.3.3 连锁懒加载执行逻辑
1.  触发条件：当返回值为「实体类型变量」「list[实体类型]变量」或「实体类型实例」时，自动触发连锁懒加载；
2.  执行流程：
    - 第一步：加载当前实体的所有基础字段（如`User`的`user_id`、`username`、`balance`等）；
    - 第二步：遍历该实体的所有关联配置（一对一/一对多/多对多），递归查询关联实体数据（如`User`关联的`Order`列表、`Coupon`列表）；
    - 第三步：对关联实体重复第一步与第二步，直到补全所有层级的关联数据（可通过配置限制最大递归层级，避免无限加载）；
    - 第四步：将完整的实体结构返回给外部调用方；
3.  配置项：支持通过注解配置懒加载层级，示例：`@LazyLoad(level=2) GetUserProfile(...)`（仅加载2层关联数据，如`User`→`Order`→`OrderItem`，不加载`OrderItem`关联的`Goods`）；
4.  优势：无需手动编写多步关联查询语句，通过返回实体变量自动补全完整数据结构，简化开发流程，保证数据一致性。

## 五、自然语义控制语法（缩进式，无大括号）
### 5.1 判断语法（贴合英语表达习惯+缩进式作用域）
#### 5.1.1 基础单条件判断
- 语法格式（完全贴合英语逻辑，冒号+缩进界定作用域）：
  ```
  If [条件表达式] Then:
      满足条件时执行的语句（缩进1级）
      满足条件时执行的语句（同层级缩进）
  ```
- 简化格式（省略`Then`，保持简洁性）：
  ```
  If [条件表达式]:
      满足条件时执行的语句
  ```
- 条件表达式：支持比较运算（`is equal to`/`is greater than`等自然表述，兼容`==`/`>`/`<`等符号）、逻辑运算（`And`/`Or`/`Not`），变量需用`{}`标识，支持`list`参数的`is in`/`is not in`判断；
- 示例1（自然表述条件）：
  ```
  If {sender.balance} is less than {amount} Then:
      throw "Insufficient balance for transfer"
  ```
- 示例2（list参数判断）：
  ```
  If {user.id} is not in {valid_user_ids}:
      throw "User {user.id} is not allowed to perform this operation"
  ```

#### 5.1.2 条件分支判断（If-Else If-Else）
- 语法格式（贴合英语语义，缩进保持一致层级）：
  ```
  If [条件1] Then:
      满足条件1的执行语句（缩进1级）
  Else If [条件2] Then:
      满足条件2的执行语句（同层级缩进）
  Else:
      不满足所有条件的执行语句（同层级缩进）
  ```
- 简化格式（省略`Then`）：
  ```
  If [条件1]:
      满足条件1的执行语句
  Else If [条件2]:
      满足条件2的执行语句
  Else:
      不满足所有条件的执行语句
  ```
- 示例（订单折扣判断，含默认值参数+list参数，适配返回值规则）：
  ```
  If {buyer.vip_level} is equal to 3:
      Set {final_discount} = 0.7
  Else If {buyer.id} is in {high_consumption_user_ids}:
      Set {final_discount} = 0.8
  Else:
      Set {final_discount} = {discount}  // 引用真实类型默认值参数
  // 后续可直接返回{final_discount}
  ```

#### 5.1.3 条件表达式补充
| 自然英语表述          | 等价符号 | 说明                  | 示例                                  |
|-----------------------|----------|-----------------------|---------------------------------------|
| `is equal to`         | `==`     | 等于                  | `{user.status} is equal to 'active'`  |
| `is not equal to`     | `!=`     | 不等于                | `{order.status} is not equal to 'cancelled'` |
| `is greater than`     | `>`      | 大于                  | `{total} is greater than 1000`        |
| `is greater than or equal to` | `>=` | 大于等于 | `{balance} is greater than or equal to 0` |
| `is less than`        | `<`      | 小于                  | `{stock} is less than 10`             |
| `is less than or equal to` | `<=` | 小于等于 | `{discount} is less than or equal to 1` |
| `is in`               | `in`     | 存在于list伪类型/集合 | `{user.id} is in {valid_user_ids}`    |
| `is not in`           | `not in` | 不存在于list伪类型/集合 | `{goods.id} is not in {invalid_ids}`  |
| `is null`             | -        | 为空                  | `{user.email} is null`                |
| `is not null`         | -        | 不为空                | `{order.pay_time} is not null`        |
| `And`                 | `&&`     | 逻辑与                | `{vip_level} > 1 And {total} > 500`   |
| `Or`                  | `||`     | 逻辑或                | `{has_coupon} Or {is_vip}`            |
| `Not`                 | `!`      | 逻辑非                | `Not ({order.status} is 'paid')`      |

### 5.2 循环语法（贴合英语表达习惯+缩进式作用域，适配list伪类型）
#### 5.2.1 遍历列表（For Each，核心适配list伪类型）
- 核心语法（完全贴合英语语义，优先推荐）：
  ```
  For Each [元素变量名] in [list变量] Do:
      循环执行的语句（缩进1级）
      循环执行的语句（同层级缩进）
  ```
- 简化格式（省略`Do`，保持简洁）：
  ```
  For Each [元素变量名] in [list变量]:
      循环执行的语句
  ```
- 说明：`元素变量名`为自定义变量，指向list中当前遍历的元素（引用时需加`{}`）；`list变量`为`list`伪类型参数或函数内批量实体集合（引用时需加`{}`）；通过缩进界定循环体作用域；
- 示例1（遍历list参数计算总价，自然格式）：
  ```
  For Each item in {orderItems} Do:
      Set {total} = {total} + {item.price} * {item.quantity}
  ```
- 示例2（遍历list参数扣减库存，简化格式）：
  ```
  For Each good in {purchasedGoods}:
      Update a goods by id of {good.id} to set stock = {good.stock} - 1
  ```

#### 5.2.2 计数循环（For From To）
- 核心语法（贴合英语计数表达）：
  ```
  For [计数变量] From [起始值] To [结束值] Step [步长] Do:
      循环执行的语句（缩进1级）
  ```
- 简化格式（省略`Do`，步长默认1可省略）：
  ```
  For [计数变量] From [起始值] To [结束值]:
      循环执行的语句
  ```
- 说明：`计数变量`自动生成，无需提前定义（引用时需加`{}`）；`Step`指定步长（正数递增，负数递减），默认步长为1；
- 示例（递增循环生成日志，适配返回值规则）：
  ```
  For index From 1 To 10:
      Create a log with a content of "Batch operation: " + {index}
  // 后续可返回日志列表{batch_logs}
  ```

#### 5.2.3 条件循环（While Do）
- 核心语法（贴合英语语义）：
  ```
  While [条件表达式] Do:
      循环执行的语句（缩进1级，需包含终止条件，避免死循环）
  ```
- 简化格式（省略`Do`）：
  ```
  While [条件表达式]:
      循环执行的语句
  ```
- 示例（重试查询直到获取有效数据，含list参数判断）：
  ```
  Set {retry_count} = 0
  While {retry_count} < 3 And {the order} is null:
      Get an order by id of {order_id} as the order
      Set {retry_count} = {retry_count} + 1
      Sleep 1000  // 休眠1秒后重试
      If {retry_count} >= 3:
          throw "Failed to query order after 3 retries"
  // 后续可返回{the order}
  ```

### 5.3 异常处理语法（自然语义+缩进式作用域）
- 核心语法（贴合英语异常捕获逻辑，适配返回值规则）：
  ```
  Try:
      可能抛出异常的业务逻辑语句（缩进1级）
  Catch [异常变量名]:
      异常处理语句（同层级缩进，如回滚事务、赋值错误变量）
  Finally:
      无论是否异常都执行的语句（同层级缩进，可选，如释放资源）
  ```
- 简化格式（省略异常变量名，无需捕获异常详情时使用）：
  ```
  Try:
      可能抛出异常的业务逻辑语句
  Catch:
      异常处理语句
  Finally:
      收尾语句
  ```
- 关键语句：`throw [异常信息]`（主动抛出异常，触发事务回滚）、`rollback`（手动回滚事务）；
- 示例（资金转账异常处理，含list参数+返回值规则）：
  ```
  Try:
      Get a user by id of {from_id} as sender
      Get a user by id of {to_id} as receiver
      If {sender.balance} is less than {amount}:
          throw "Insufficient balance: sender's balance is " + {sender.balance}
      Update the sender to set balance = {sender.balance} - {amount}
      Update the receiver to set balance = {receiver.balance} + {amount}
      // 记录转账关联用户ID（list参数）
      Create a transfer_log with a related_user_ids of {related_user_ids} and amount of {amount}
      Set {transfer_success} = true
      Set {result_order} = {the transfer_log}
  Catch transfer_error:
      rollback
      Set {transfer_success} = false
      Set {error_message} = {transfer_error}
  Finally:
      Create a transaction_log with a content of "Transfer from " + {from_id} + " to " + {to_id}
  // 按返回值规则，分别返回对应变量
  If {transfer_success}:
      return {result_order}
  Else:
      return {error_message}
  ```

## 六、函数体与数据库操作集成
### 6.1 支持的数据库操作语句
函数体内可直接使用现有数据库操作语言的所有语句，变量引用需加`{}`标识，包括：
- 查询操作：`Get a user by id of {user_id} as targetUser`、`Get [tag]s where status is 'valid' as validTags`；
- 新增操作：`Create a tag with a name of {tag_name} and color of '#FF0000' as newTag`；
- 更新操作：`Update the targetUser to set username to {new_name} and age to {new_age}`；
- 删除操作：`Delete the tag`、`Delete [user]s where status is 'inactive'`；
- 关联操作：`Get orders from the targetUser as userOrders`、`Bind [goods] to the order as orderGoods`；
- 聚合计算：`sum({order.total} for order in {userOrders})`、`length({validTags})`（`length`适配list伪类型）；
- 变量赋值：`Set {total} = 0`、`Set {final_price} = {price} * {discount}`（为返回值提供可用变量）；
- 休眠操作：`Sleep [毫秒数]`（用于重试场景）；
- 赋值逻辑结果：`Set {is_vip_user} = {user.vip_level} > 0`（为返回值提供逻辑判断结果）。

### 6.2 事务内特殊逻辑示例（适配返回值新规则+连锁懒加载）
#### 6.2.1 变量复用与计算（含list遍历+真实类型默认值+规范返回）
```
CalculateOrderTotal(
    number:order_id,
    number[3.2]:discount (default is 0.9),  // 真实类型：支持默认值
    bool:include_shipping (false),  // 真实类型：支持默认值
    list[number]:order_item_ids [not null]  // list伪类型：无默认值，必选传入

    Get a user from the order as buyer
    Get [order_item]s where id in {order_item_ids} as orderItems
    Get a shipping_fee by user_id of {buyer.user_id} as shipping_fee
    
    // 内部变量定义与初始化（为返回值准备）
    Set {total} = 0
    Set {discounted_total} = 0
    Set {final_total} = 0
    Set {shipping_fee_amount} = {shipping_fee.fee}
    
    // 遍历list伪类型参数：计算商品总价
    For Each item in {orderItems} Do:
        Set {total} = {total} + {item.price} * {item.quantity}
    
    // 应用真实类型默认折扣
    Set {discounted_total} = {total} * {discount}
    
    // 判断是否包含运费（真实类型默认值参数）
    If {include_shipping}:
        Set {final_total} = {discounted_total} + {shipping_fee_amount}
    Else:
        Set {final_total} = {discounted_total}
    
    // 数据库更新
    Update the order to set total to {total}, discounted_total to {discounted_total}, final_total to {final_total}
    Update the buyer to set balance to {buyer.balance} - {final_total}
    
    // 按新规则返回：仅返回已有变量（禁止临时{}）
    // 可选1：返回单个最终总价
    return {final_total}
    // 可选2：返回更新后的订单实体（触发连锁懒加载，含关联用户、订单项等）
    // return {the order}
    // 可选3：返回list类型的订单项（触发批量懒加载）
    // return {orderItems}
```

#### 6.2.2 多条件判断与折扣计算（含list参数校验+规范返回）

CalculateUserDiscount(

## 七、执行器设计（轻量化解析，强化list伪类型+返回值校验）
### 7.1 设计核心：最小化改造+解析简化+多维度校验
- 灵感来源：基于「缩进界定作用域」「大括号专属变量」「小括号专属真实类型默认值」「list伪类型无默认值」「返回值禁用临时{}」的设计，彻底消除语法歧义，大幅简化执行器解析逻辑，降低改造与维护成本；
- 核心思路：
  1.  缩进解析：通过识别语句缩进层级，界定函数体、判断、循环、异常处理的语句块作用域，替代原有大括号解析逻辑；
  2.  括号语义分离：大括号仅用于变量引用，小括号仅用于真实基础类型的默认值定义，执行器无需额外判断括号语义，直接按固定规则解析；
  3.  类型与默认值校验：
      - 对真实基础类型参数，解析小括号内的默认值（自然语言→关键字提取/无关键字→直接取值）；
      - 对`list`伪类型参数，强制校验是否包含默认值定义，若存在则直接抛出语法错误，确保`list`参数必选传入；
  4.  返回值严格校验：
      - 扫描`return`语句，判断返回内容是否为`{变量名}`格式或已有实体类型；
      - 若检测到临时`{}`构造（如`{key: value}`），直接抛出语法错误；
      - 校验返回变量是否已初始化（是否通过参数传入或内部赋值/`Get`操作生成），未初始化则抛出异常；
      - 若返回值为实体类型/变量，自动触发连锁懒加载逻辑，补全完整数据结构；
  5.  自然语义转换：将自然英语表述的控制语法（如`For Each`、`If ... Then`）转换为执行器可识别的底层逻辑，不修改核心执行流程；
  6.  list参数处理：将`list`参数作为数组结构直接传递，仅支持遍历、长度计算、`in`/`not in`判断，不支持默认值填充，返回时触发批量懒加载。

### 7.2 执行器解析流程（简化版，含返回值+懒加载逻辑）
1.  函数头解析与校验：
    - 识别函数名、事务注解，提取参数列表；
    - 对每个参数进行类型分类（真实基础类型/`list`伪类型/实体类型）；
    - 真实基础类型：解析小括号内的默认值，生成参数映射表（`参数名`→`{参数名}`，包含默认值配置）；
    - `list`伪类型：校验是否存在默认值定义（`()`/`default is`等），若存在则抛出语法异常；仅提取参数名与约束属性，加入参数映射表（无默认值）；
    - 实体类型参数：校验是否为预先定义的类型，未定义则抛出异常；
2.  缩进层级识别：遍历函数体语句，记录每条语句的缩进层级，建立「缩进层级-语句块」映射关系；
3.  变量识别与初始化跟踪：
    - 扫描所有语句，识别`{xxx}`格式的变量引用，通过参数映射表匹配对应参数；
    - 跟踪内部变量的初始化状态（`Set`赋值/`Get`操作生成），生成变量初始化映射表；
4.  控制语法解析：针对自然语义控制语句（判断/循环/异常处理），按缩进层级转换为底层执行逻辑（如`For Each`转换为list数组遍历逻辑）；
5.  数据库操作执行：按原有逻辑执行各类数据库操作，通过变量映射表获取变量值（真实类型参数默认值自动填充未传入的参数，`list`参数需强制传入）；
6.  返回值校验与懒加载执行：
    - 校验`return`语句：是否为合法变量/实体类型，是否包含临时`{}`，变量是否已初始化；
    - 若返回值为实体类型/变量/`list[实体类型]`变量，触发连锁懒加载：
      - 加载当前实体基础字段；
      - 递归加载所有关联实体数据（按配置层级限制）；
      - 组装完整数据结构；
    - 若返回值为基础类型变量，直接提取变量值；
7.  结果组装与返回：将处理后的返回值（完整实体结构/基础变量值/list数据）返回给外部调用方。

### 7.3 执行器改造亮点
- 解析极致轻量化：括号语义完全分离，类型、默认值、返回值的约束清晰，无需处理复杂的歧义场景，大幅降低解析复杂度与出错概率；
- 多维度强校验：包含list伪类型默认值校验、返回值合法性校验、变量初始化校验，提升函数执行的规范性与可靠性；
- 连锁懒加载自动化：返回实体时自动补全所有关联数据，无需手动编写关联查询，简化开发流程，提升数据可用性；
- 默认值解析高效：真实类型小括号内默认值支持双写法，执行器通过关键字快速识别与提取，不增加解析开销；
- 无侵入性：原有数据库操作执行逻辑完全保留，仅新增「缩进解析」「括号语义解析」「类型与默认值校验」「返回值校验」「懒加载执行」步骤，不影响现有功能；
- 高效性：所有解析、校验与懒加载步骤仅在解析/执行阶段执行一次，不增加运行时额外开销；
- 扩展性：未来可通过「自然语义转换层」扩展更多英语表述语法，通过配置扩展懒加载层级、返回值类型过滤等功能，无需修改核心执行逻辑；
- 易用性：缩进式语法+自然语义表述符合大众使用习惯，清晰的类型与返回值规则降低学习成本，便于开发者快速上手。

// 配置懒加载层级：仅加载2层关联数据（User→Order→OrderItem，不加载Goods）
@LazyLoad(level=2)
GetUserProfile(
    number:user_id,
    bool:include_order_stats (true),  // 真实类型：默认值true

    Get a user by id of {user_id} as targetUser
    
    // 查询关联标签（排除指定标签ID，list参数）
    Get [tag]s from the targetUser where id not in {exclude_tag_ids} as userTags

    Set {completed_order_count} = 0

    // 判断是否包含订单统计（真实类型默认值参数）

        // 查询指定时间范围内的订单（生成list变量userOrders/completedOrders）

### 8.2 复杂示例：商品购买事务（完整适配返回值新规则+连锁懒加载）
```
// 可按需指定非默认隔离级别，此处演示配置REPEATABLE_READ
@Isolation(REPEATABLE_READ)
@LazyLoad(level=3)  // 懒加载3层：Order→OrderItem→Goods→Coupon
PurchaseGoods(
    number:user_id,
    list[number]:goods_ids [not null],  // list伪类型：无默认值，必选传入
    number[10.2]:coupon_discount (default is 0),  // 真实类型：默认值0
    str[20]:coupon_code (""),  // 真实类型：默认值空字符串
    bool:is_vip (with default value false)  // 真实类型：进阶自然语言默认值
):
    // 内部变量初始化（为返回值准备）
    Set {purchase_success} = false
    Set {error_msg} = ""
    Set {new_order} = null
    
    Try:
        // 1. 查询用户与商品（list参数+真实类型参数引用）
        Get a user by id of {user_id} as buyer
        Get [goods]s where id in {goods_ids} as purchasedGoods
        
        // 2. 验证优惠券（真实类型默认值参数）
        If {coupon_code} != "":
            Get a coupon by code of {coupon_code} and user_id of {user_id} as user_coupon
            If {user_coupon} is null Or Not {user_coupon.is_valid}:
                throw "Invalid or expired coupon code: " + {coupon_code}
            Set {actual_coupon_discount} = {user_coupon.discount}
        Else:
            Set {actual_coupon_discount} = {coupon_discount}
        
        // 3. 计算用户折扣（调用自定义函数，传入list参数）
        Set {user_discount} = CalculateUserDiscount({user_id}, {coupon_code}, {vip_user_ids})
        Set {final_discount} = {user_discount} * (1 - {actual_coupon_discount})
        
        // 4. 业务校验：商品库存充足（遍历list参数）
        For Each good in {purchasedGoods} Do:
            If {good.stock} is less than 1:
                throw "Good " + {good.id} + " (name: " + {good.name} + ") is out of stock"
        
        // 5. 计算订单总价（遍历list参数）
        Set {total} = 0
        For Each good in {purchasedGoods}:
            Set {total} = {total} + {good.price}
        Set {final_total} = {total} * {final_discount}
        
        // 6. 校验用户余额
        If {buyer.balance} is less than {final_total}:
            throw "Insufficient balance: your balance is " + {buyer.balance} + ", need " + {final_total}
        
        // 7. 扣减用户余额与商品库存
        Update the buyer to set balance = {buyer.balance} - {final_total}, total_consumption = {buyer.total_consumption} + {final_total}
        For Each good in {purchasedGoods}:
            Update a goods by id of {good.id} to set stock = {good.stock} - 1, sales_volume = {good.sales_volume} + 1
        
        // 8. 创建订单（生成实体变量newOrder）
        Create an order with 
            a user_id of {user_id} and 
            a total of {total} and 
            a final_total of {final_total} and 
            a discount_rate of {final_discount} and 
            a coupon_code of {coupon_code} and 
            a status of 'paid' and 
            a create_time of datetime.now() 
            as newOrder
        Set {new_order} = {newOrder}
        
        // 9. 绑定订单与商品（n-n关联，自然循环）
        For Each good in {purchasedGoods} Do:
            Bind [goods] to the newOrder with relation_type of 'purchased'
            Create an order_item with 
                a order_id of {newOrder.order_id} and 
                a goods_id of {good.id} and 
                a goods_name of {good.name} and 
                a price of {good.price} and 
                a final_price of {good.price} * {final_discount}
        
        // 10. 更新优惠券状态（若使用优惠券）
        If {coupon_code} != "":
            Update the user_coupon to set is_used = true, used_time = datetime.now(), order_id = {newOrder.order_id}
            // 关联优惠券到订单
            Bind [coupon] to the newOrder with relation_type of 'used'
        
        // 11. 标记购买成功
        Set {purchase_success} = true
        
    Catch purchase_error:
        rollback
        Set {purchase_success} = false
        Set {error_msg} = {purchase_error}
    
    Finally:
        // 记录购买日志
        Create a purchase_log with 
            a user_id of {user_id} and 
            a goods_ids of {goods_ids} and 
            a order_id of {new_order.order_id} and 
            a operation_time of datetime.now() and 
            a status of If ({purchase_success}) Then 'success' Else 'failed' and 
            a remark of "VIP: " + {is_vip} + ", Coupon used: " + ({coupon_code} != "")
        Set {purchase_log} = {the purchase_log}
    
    // 按新规则返回：根据购买结果返回对应合法变量（禁止临时{}）
    If {purchase_success}:
        // 返回订单实体（触发连锁懒加载：Order→OrderItem→Goods→Coupon→PurchaseLog）
        return {new_order}
    Else:
        // 返回错误信息变量
        return {error_msg}
    
    // 其他合法返回选项：
    // 1. 返回购买日志实体
    // return {purchase_log}
    // 2. 返回购买成功标识（布尔变量）
    // return {purchase_success}
    // 3. 返回购买商品列表（list类型）
    // return {purchasedGoods}
```

## 九、与现有语法体系的兼容性
### 9.1 数据库操作语言兼容
- 完全复用冠词规则：`a/an`（新单实体）、`the`（已获取实体）、复数/`[]`（批量实体）的语义与用法保持一致；
- 变量规则兼容：默认变量生成、`the + 实体名`定位、显式变量命名（`as`）等逻辑完全复用，仅新增`{}`变量标识与返回值规则；
- 操作语句兼容：查询、新增、更新、删除、关联等操作的语法结构不变，仅需为变量添加`{}`标识，为返回值准备合法变量；
- 执行策略兼容：事务函数内自动禁用懒加载/懒查找（确保操作即时执行，保证数据一致性），仅在返回实体时触发主动连锁懒加载；
- 控制语法兼容：缩进式自然语义语法与原有简洁语法可平滑过渡，执行器自动兼容解析；
- list类型兼容：函数内批量实体查询结果的用法不变，仅明确其伪类型属性，不支持默认值配置，可直接作为返回值。

### 9.2 数据库结构描述语言兼容
- 类型定义兼容：函数参数真实类型（`number[P.S]`、`str[L]`等）与实体字段类型定义规则完全一致；
- 约束规则兼容：参数约束（`[not null]`、`[unique]`等）与实体字段约束逻辑一致，真实类型默认值定义可无缝衔接现有约束体系；
- 实体类型兼容：预先定义的实体结构（字段+关联关系）可直接作为返回值类型，连锁懒加载逻辑复用现有关联查询规则；
- list伪类型兼容：`list`仅作为函数内临时结构描述，不影响数据库底层结构定义，关联查询结果可直接适配`list`参数传递与返回。

## 十、核心优势总结
1.  事务-函数一体化：无需额外配置，函数即事务，既支持外部调用，又能保证数据一致性，简化复杂业务开发；
2.  精度可控无丢失：`number[P.S]`定点小数类型，精准适配金额、比例等场景，彻底解决浮点数精度问题；
3.  数据优先保障：默认采用`SERIALIZABLE`最高隔离级别，最大化规避事务并发问题，优先保证数据准确性；
4.  自然语义友好：判断、循环、参数默认值等语法贴合英语表达习惯，搭配缩进式写法，降低理解与学习成本，提升代码可读性；
5.  解析极致轻量化：括号语义完全分离（大括号=变量，小括号=真实类型默认值），list伪类型无默认值、返回值禁用临时{}规则清晰，消除所有语法歧义，大幅降低执行器解析复杂度与出错概率；
6.  类型规则明确：真实基础类型支持灵活默认值配置，list伪类型强制必选传入，返回值仅允许已有变量/类型，边界清晰，提升函数调用的规范性与可靠性；
7.  连锁懒加载自动化：返回实体时自动补全所有关联数据，无需手动编写多步关联查询，简化开发流程，保证返回数据的完整性与可用性；
8.  执行器低改造：基于缩进解析、括号专属语义、多维度校验的设计，无需重构现有执行器核心逻辑，开发成本低、落地快；
9.  体系无缝衔接：完全复用现有数据库语言的类型规则、变量逻辑、操作语法，学习成本低，迁移平滑；
10. 结构清晰易维护：函数化组织事务逻辑，换行排版优化复杂语句可读性，缩进层级明确作用域，规范的返回值规则便于调试与迭代；
11. 扩展能力强：自然语义语法与真实类型默认值配置支持灵活扩展，list伪类型、懒加载层级可通过配置扩展，无需修改核心执行逻辑，可适配未来业务需求变化。
