# 动态关联型数据库设计文档（精简版）
## 一、核心目标与解决的痛点
### 1.1 核心目标
用「简洁DSL+自动映射+专属关联表」，让开发者无需关注底层数据库设计，通过自动化生成专属关联表和业务代码，快速实现实体关联与权限场景。

### 1.2 解决的核心问题
- 无需预先定义实体关系：支持运行时动态绑定（如仓库授权、资源分享），不用改表结构；
- 避免重复数据与同步麻烦：非基本类型自动存ID引用，不冗余存储实体内容；
- 简化关联表设计：为每个n-n关系自动生成专属复合主键关联表，无需手动建表；
- 降低开发门槛：读写操作与普通表一致，复合主键无额外学习成本，业务代码全自动化生成；
- 兼容主流数据库：自动适配MySQL/PostgreSQL/SQLite，无需手动适配语法；
- 兼顾性能与清晰性：专属关联表数据量小、查询高效，结构清晰易调试。

## 二、核心语法规则（DSL）
### 2.1 核心约定
- 实体定义：`实体名{ 字段列表 }`（对应数据库表名格式：`数据库名_实体名小写`）；
- 基本类型：`类型:字段名 [属性]`（直接存值），所有类型长度/精度约束统一使用中括号`[]`，支持`number/number[整数位.小数位]/str[长度]/datetime/bool`；
- 非基本类型：`实体名:字段名`（1-n关联，存储目标实体ID）/`List[实体名]:字段名`（n-n关联，触发专属关联表生成），`List`作为关联集合标识，统一语法格式；
- 主键：显式`number:xxx [primary]`或默认生成`default_id`（自增）；
- 默认值语法：使用小括号`()`为字段指定默认值，格式为`类型:字段名 (默认值)`，可与属性标签搭配使用。

### 2.2 极简示例（.st文件）
```st
# 数据库：test
# 用户实体（定义n-n关联Tag，包含数值精度与默认值）
User{
    number:user_id [primary]
    str[50]:user_name [not null unique]
    number[3.4]:account_balance (0.0000) [not null] # 定点小数：3位整数+4位小数，默认值0.0000
    int[11]:age (18) # 整数类型（长度11），默认值18
    bool:is_active (true) [not null] # 布尔类型，默认值true
    str[11]:phone (13800138000) # 字符串类型（长度11），默认值13800138000
    datetime:create_time (CURRENT_TIMESTAMP) [not null] # 日期时间类型，默认当前时间
    List[Tag]:tags # n-n关联，触发test_user_tag专属表生成
}

# 仓库实体（包含默认值配置）
Warehouse{
    number:warehouse_id [primary]
    str[50]:warehouse_name [not null]
    str[200]:address (未填写) # 字符串类型（长度200），默认值"未填写"
    number[5.2]:area (0.00) [not null] # 定点小数：5位整数+2位小数，默认值0.00
    List[User]:authorized_users # n-n关联，触发test_warehouse_user专属表生成
}

# 标签实体（被其他实体引用，包含默认值）
Tag{
    number:tag_id [primary]
    str[32]:tag_name [not null unique]
    str[16]:tag_color ('#FFFFFF') [default] # 字符串类型（长度16），默认值'#FFFFFF'
    str[100]:description (无标签描述) # 字符串类型（长度100），默认值"无标签描述"
}
```

## 三、核心机制
### 3.1 类型驱动存储
- 基本类型：
  1.  普通数值`number`：直接存储整数或默认精度小数，映射数据库INT/DECIMAL类型；
  2.  定点小数`number[整数位.小数位]`：精准存储带固定精度的数值（如金额、面积），映射数据库DECIMAL(整数位+小数位, 小数位)类型，避免精度丢失；
  3.  字符串`str[长度]`：存储指定最大长度的字符串，映射数据库VARCHAR(长度)类型；
  4.  布尔`bool`：存储布尔值，映射数据库BOOLEAN/TINYINT(1)类型；
  5.  日期时间`datetime`：存储日期时间，映射数据库DATETIME类型；
  6.  默认值：小括号`()`内的默认值会自动带入数据库表字段的DEFAULT属性，支持常量值（如18、'#FFFFFF'）和数据库函数（如CURRENT_TIMESTAMP）；
- 非基本类型：仅存主键ID（如`Warehouse:my_warehouse`存`warehouse_id`；`List[Tag]:tags`不存储ID，由专属关联表维护关联关系）。

### 3.2 专属关联表生成规则（自动化执行）
所有n-n关系（`List[实体名]:字段名`形式）默认生成专属关联表，规则如下：
| 规则项         | 具体逻辑                                                                 |
|----------------|--------------------------------------------------------------------------|
| 表名           | `数据库名_实体1名小写_实体2名小写`（实体名按字母序，避免重复，如User-Tag→test_user_tag） |
| 字段           | 必含：`实体1_id`（外键）、`实体2_id`（外键）；可选：`relation_type`（关联类型，默认'default'）、`create_time`（创建时间，默认当前时间） |
| 主键           | 复合主键：`实体1_id + 实体2_id`（确保关联关系唯一，防重复绑定）|
| 外键约束       | 分别关联两个实体的主键，级联删除（`ON DELETE CASCADE`）|
| 索引           | 自动生成复合主键索引，额外为单个ID字段生成普通索引（优化单实体查询）|

### 3.3 专属关联表示例（自动生成）
#### 1. User-Tag专属关联表（test_user_tag）
```sql
CREATE TABLE test_user_tag (
  -- 核心关联字段（复合主键）
  user_id INT NOT NULL,
  tag_id INT NOT NULL,
  -- 可选扩展字段（自动生成，包含默认值）
  relation_type VARCHAR(32) DEFAULT 'default', -- 关联类型（如owner/authorize）
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  -- 复合主键（确保唯一）
  PRIMARY KEY (user_id, tag_id),
  -- 外键约束（级联删除）
  FOREIGN KEY (user_id) REFERENCES test_user(user_id) ON DELETE CASCADE,
  FOREIGN KEY (tag_id) REFERENCES test_tag(tag_id) ON DELETE CASCADE,
  -- 优化索引（自动生成）
  INDEX idx_tag_id (tag_id)
);
```

#### 2. Warehouse-User专属关联表（test_warehouse_user）
```sql
CREATE TABLE test_warehouse_user (
  warehouse_id INT NOT NULL,
  user_id INT NOT NULL,
  relation_type VARCHAR(32) DEFAULT 'authorize',
  create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (warehouse_id, user_id),
  FOREIGN KEY (warehouse_id) REFERENCES test_warehouse(warehouse_id) ON DELETE CASCADE,
  FOREIGN KEY (user_id) REFERENCES test_user(user_id) ON DELETE CASCADE,
  INDEX idx_user_id (user_id)
);
```

### 3.4 自动化生成逻辑
1. 解析阶段：解析`.st`文件，识别所有`List[实体名]:字段名`形式的n-n关系（提取关联实体）、`number[整数位.小数位]`精度约束、`()`默认值配置；
2. 建表阶段：按专属表规则拼接建表SQL，将`number[X.Y]`映射为DECIMAL(X+Y, Y)、`str[L]`映射为VARCHAR(L)、`()`内默认值映射为字段DEFAULT属性，自动适配目标数据库语法；
3. 代码生成阶段：同步生成专属关联表的CRUD业务代码（绑定/解绑/查询），无需人工编写。

## 四、核心使用示例（JS，自动化生成）
### 4.1 仓库授权给用户（基于test_warehouse_user专属表）
```javascript
// 自动生成：给仓库绑定授权用户
async function grantWarehouse(warehouseId, userId, relationType = 'authorize') {
  await db.execute(`
    INSERT INTO test_warehouse_user (warehouse_id, user_id, relation_type) 
    VALUES (?, ?, ?)
  `, [warehouseId, userId, relationType]);
}

// 自动生成：查询用户的所有授权仓库
async function getUserAuthorizedWarehouses(userId) {
  const [rows] = await db.execute(`
    SELECT w.* FROM test_warehouse w
    JOIN test_warehouse_user wu ON w.warehouse_id = wu.warehouse_id
    WHERE wu.user_id = ? AND wu.relation_type = 'authorize'
  `, [userId]);
  return rows;
}

// 自动生成：取消仓库对用户的授权
async function revokeWarehouse(warehouseId, userId) {
  await db.execute(`
    DELETE FROM test_warehouse_user 
    WHERE warehouse_id = ? AND user_id = ?
  `, [warehouseId, userId]);
}
```

### 4.2 用户绑定标签+更新账户余额（基于test_user_tag/test_user表）
```javascript
// 自动生成：给用户绑定标签
async function bindUserTag(userId, tagId, relationType = 'default') {
  await db.execute(`
    INSERT INTO test_user_tag (user_id, tag_id, relation_type) 
    VALUES (?, ?, ?)
  `, [userId, tagId, relationType]);
}

// 自动生成：查询用户的所有标签与账户余额
async function getUserTagsAndBalance(userId) {
  const [userRows] = await db.execute(`
    SELECT user_name, account_balance FROM test_user WHERE user_id = ?
  `, [userId]);
  
  const [tagRows] = await db.execute(`
    SELECT t.* FROM test_tag t
    JOIN test_user_tag ut ON t.tag_id = ut.tag_id
    WHERE ut.user_id = ?
  `, [userId]);
  
  return {
    userInfo: userRows[0],
    tags: tagRows
  };
}

// 自动生成：更新用户账户余额（兼容number[3.4]精度约束）
async function updateUserBalance(userId, newBalance) {
  // 自动校验精度：newBalance需满足3位整数+4位小数
  const balanceRegex = /^[0-9]{1,3}\.[0-9]{4}$/;
  if (!balanceRegex.test(newBalance.toString())) {
    throw new Error(`账户余额${newBalance}超出number[3.4]精度约束（3位整数+4位小数）`);
  }
  
  await db.execute(`
    UPDATE test_user SET account_balance = ? WHERE user_id = ?
  `, [newBalance, userId]);
}
```

## 五、核心优点
1.  动态灵活：运行时绑定实体，无需预先定义关系，适配授权/分享场景；
2.  语法统一：所有类型约束（数值精度、字符串长度、关联集合）均使用中括号`[]`，小括号`()`统一承载默认值配置，无格式冲突，降低学习成本；
3.  精度无损：`number[整数位.小数位]`精准映射数据库定点小数类型，彻底解决金额、计量类数据的精度丢失问题；
4.  自动高效：自动生成主表（含默认值、精度约束）、专属关联表（复合主键+索引），业务代码全自动化，无人工维护成本；
5.  性能更优：专属表仅存储单一n-n关系，数据量小，复合主键索引查询效率远高于通用关联表；
6.  结构清晰：每个n-n关系对应一张专属表，字段默认值与精度一目了然，排查问题可直接定位；
7.  数据一致：外键+级联删除，避免脏数据和重复关联；
8.  读写简单：复合主键、精度约束、默认值的操作与普通表一致，无额外学习成本；
9.  兼容广泛：支持MySQL/PostgreSQL/SQLite，纯JS解析无外部依赖。

## 六、适用场景
- 权限管理（用户-角色-资源授权）；
- 资源分享（仓库、文件、项目多用户共享）；
- 金融/计量场景（需精准小数精度的账户余额、商品价格、面积计量等）；
- 快速原型开发（无需关注数据库设计，仅需定义.st实体）；
- 关系频繁变更的灵活业务系统；
- 业务代码自动化生成的场景（屏蔽关联表维护成本）。
