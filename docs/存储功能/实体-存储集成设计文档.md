# 实体-存储集成设计文档

## 一、核心设计目标

通过「内置EJS模块+实体交互器+存储引擎」的三层架构，实现实体系统与存储系统的无缝集成，让开发者可以在实体中直接访问存储系统，无需通过路由间接访问。

## 二、核心设计理念

1. **极简语法**：保持现有实体DSL的简洁性，通过内置EJS模块提供存储访问能力
2. **无缝集成**：实体可以直接访问存储系统，无需额外配置
3. **类型安全**：提供类型安全的存储访问API
4. **事务支持**：支持实体方法在事务中执行
5. **自动映射**：自动实现实体到数据库的映射
6. **兼容现有系统**：不破坏现有系统的结构和功能

## 三、核心架构

### 1. 三层架构


## 四、核心功能设计

### 1. 内置EJS模块

#### 1.1 db.ejs - 数据库访问模块

**功能**：提供数据库访问API，包括查询、插入、更新、删除等操作

**核心API**：
- `query(sql, params)` - 执行SQL查询
- `insert(table, data)` - 插入数据
- `update(table, data, where)` - 更新数据
- `delete(table, where)` - 删除数据
- `get(table, id)` - 根据ID获取数据
- `find(table, where)` - 根据条件查找数据

#### 1.2 storage.ejs - 存储引擎访问模块

**功能**：提供存储引擎访问API，包括获取数据库、表结构、事务等

**核心API**：
- `getDatabase(dbName)` - 获取数据库
- `getTable(dbName, tableName)` - 获取表结构
- `getTransaction(dbName, transactionName)` - 获取事务
- `executeTransaction(dbName, transactionName, params)` - 执行事务
- `generateCreateTableSQL(dbName, tableName)` - 生成建表SQL

#### 1.3 entity-mapper.ejs - 实体映射模块

**功能**：提供实体到数据库的映射API

**核心API**：
- `mapEntityToTable(entity)` - 将实体映射到数据库表
- `mapTableToEntity(table, entityType)` - 将数据库表映射到实体
- `saveEntity(entity)` - 保存实体到数据库
- `loadEntity(entityType, id)` - 从数据库加载实体

#### 1.4 transaction.ejs - 事务管理模块

**功能**：提供事务管理API

**核心API**：
- `beginTransaction()` - 开始事务
- `commit()` - 提交事务
- `rollback()` - 回滚事务
- `inTransaction()` - 检查是否在事务中

### 2. 实体交互器扩展

**功能**：扩展实体交互器，支持内置EJS模块的导入和使用

**核心改进**：
- 在实体执行器中注入存储引擎
- 支持从core/ejs-modules目录导入内置EJS模块
- 提供类型安全的存储访问API

### 3. 路由调用实体方法

**功能**：支持路由通过实体交互器调用实体方法，更改实体属性

**核心改进**：
- 提供类型转换机制，将JS参数转换为实体参数
- 提供类型转换机制，将实体返回值转换为JS值
- 支持事务管理

## 五、核心实现细节

### 1. 内置EJS模块导入机制

**语法**：
```
import db from '@core/db.ejs'
import storage from '@core/storage.ejs'
```

**实现**：
- 在实体执行器中添加特殊处理，识别@core前缀
- 将@core前缀映射到core/ejs-modules目录
- 加载内置EJS模块并注入存储引擎

### 2. 存储引擎注入机制

**实现**：
```javascript
// 在实体执行器中注入存储引擎
this.storageEngine = storageEngine;

// 在创建EJS方法执行器时，将存储引擎注入上下文
const ejsMethod = (...args) => {
    try {
        const context = {
            ...entityState,
            ...this.getJudgeFunctions(entity, entityState),
            args: args,
            storage: this.storageEngine, // 注入存储引擎
            db: this.storageEngine        // 注入数据库访问
        };
        
        const result = eval(`(function() { ${ejsContent} }).call(context)`);
        return result;
    } catch (error) {
        console.error(`Error executing imported ejs method ${name}:`, error);
        return null;
    }
};
```

### 3. 类型转换机制

**实现**：
- 为实体参数和返回值提供类型转换
- 支持基本类型、对象类型、数组类型的转换
- 支持实体类型到JS对象的转换

### 4. 事务管理机制

**实现**：
- 在实体方法执行前检查是否需要事务
- 如果需要事务，自动开始事务
- 在方法执行成功后提交事务
- 在方法执行失败后回滚事务

## 六、使用示例

### 1. 实体使用内置EJS模块

```
// 导入内置EJS模块
import db from '@core/db.ejs'
import entityMapper from '@core/entity-mapper.ejs'

User{
    number user_id [primary]
    string username [not null unique]
    number age
    bool is_active (true) [not null]
    
    void SaveUser(){
        // 使用实体映射模块保存实体
        entityMapper.saveEntity(this);
    }
    
    User FindUser(number id){
        // 使用数据库访问模块查找用户
        const userData = db.get('user', id);
        // 使用实体映射模块将数据库数据映射到实体
        return entityMapper.mapTableToEntity(userData, 'User');
    }
    
    void UpdateUser(number id, string newUsername){
        // 使用数据库访问模块更新用户
        db.update('user', { username: newUsername }, { user_id: id });
    }
}
```

### 2. 路由调用实体方法

```javascript
// 路由配置
const config = {
    method: 'POST',
    transaction: true // 启用事务
};

// 路由处理函数
const create_user = async (ctx) => {
    try {
        // 获取实体执行器
        const entityExecutor = ctx.entities;
        
        // 获取用户实体（单例）
        const userEntity = entityExecutor.getEntity('user', 'User');
        
        // 调用实体方法，创建用户
        const newUser = userEntity.recruit();
        newUser.username = ctx.request.body.username;
        newUser.age = ctx.request.body.age;
        newUser.is_active = true;
        
        // 保存用户
        newUser.SaveUser();
        
        ctx.body = {
            success: true,
            message: '用户创建成功',
            data: {
                user_id: newUser.user_id,
                username: newUser.username,
                age: newUser.age,
                is_active: newUser.is_active
            }
        };
    } catch (error) {
        ctx.throw(500, error.message);
    }
};
```

## 八、预期效果

### 1. 开发者体验

**之前**：
- 实体无法直接访问存储系统
- 需要通过路由间接访问存储系统
- 没有类型安全的存储访问API
- 没有事务支持

**之后**：
- 实体可以直接访问存储系统
- 提供类型安全的存储访问API
- 支持事务管理
- 自动实现实体到数据库的映射

### 2. 系统架构

**之前**：
- 路由系统和存储系统之间有直接访问
- 实体系统和存储系统之间没有直接访问

**之后**：
- 路由系统、实体系统、存储系统之间有直接访问
- 形成完整的三层架构
- 支持事务管理

### 3. 性能和可靠性

**之前**：
- 实体无法直接访问存储系统，需要通过路由间接访问，性能较差
- 没有事务支持，可靠性较差

**之后**：
- 实体可以直接访问存储系统，性能较好
- 支持事务管理，可靠性较好
- 自动实现实体到数据库的映射，减少错误

## 九、兼容和迁移

### 1. 兼容性

- 兼容现有实体定义
- 兼容现有路由定义
- 兼容现有存储系统

### 2. 迁移方案

- 对于现有实体，不需要修改，可以直接使用内置EJS模块
- 对于现有路由，不需要修改，可以直接调用实体方法
- 对于现有存储系统，不需要修改，可以直接使用

## 十、结论

通过内置EJS模块和实体交互器扩展，可以实现实体系统与存储系统的无缝集成，打通路由、实体、存储三者之间的调用。这将提高开发者体验，提高系统性能和可靠性，同时保持系统的兼容性和可扩展性。
