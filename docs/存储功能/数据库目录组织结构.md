# 数据库目录组织结构

## 1. 目录结构设计

### 1.1 一级文件夹结构
- **数据库配置文件夹**：一级文件夹下的文件夹名即为数据库名
- **配置文件**：用于配置数据库的账号、密码、IP等信息
- **默认配置**：若未提供配置文件，默认使用单文件SQL数据库

### 1.2 二级文件夹结构
- **表文件**：每个`.st`（storage table）文件代表一个表
- **事务文件**：每个`.dtf`（database transaction file）文件代表一个数据库事务

## 2. 文件类型定义

### 2.1 配置文件
- **文件名**：`config.json`或`config.yaml`
- **用途**：存储数据库连接信息、账号密码、IP地址等配置
- **示例**：
  ```json
  {
    "type": "mysql",
    "host": "localhost",
    "port": 3306,
    "username": "root",
    "password": "password",
    "database": "mydb"
  }
  ```

### 2.2 表文件（.st）
- **文件名**：`表名.st`
- **用途**：定义数据库表结构，包括字段、类型、约束等
- **示例**：
  ```st
  User{
      number:user_id [primary]
      str[50]:user_name [not null unique]
      number[3.2]:account_balance (0.00)
  }
  ```

### 2.3 事务文件（.dtf）
- **文件名**：`事务名称.dtf`
- **用途**：定义数据库事务逻辑，包含原子操作序列
- **示例**：
  ```dtf
  @Isolation(REPEATABLE_READ)
  TransferFund(
      number:from_user_id,
      number:to_user_id,
      number[10.2]:amount
  ):
      Try:
          Get a user by id of {from_user_id} as sender
          Get a user by id of {to_user_id} as receiver
          
          If {sender.balance} < {amount}:
              throw "Insufficient balance"
          
          Update the sender to set balance = {sender.balance} - {amount}
          Update the receiver to set balance = {receiver.balance} + {amount}
          
          return true
      Catch:
          rollback
          return false
  ```

## 3. 目录结构示例

```
storage/
├── mydb/                    # 数据库名
│   ├── config.json          # 数据库配置文件
│   ├── User.st              # 用户表定义
│   ├── Order.st             # 订单表定义
│   ├── Product.st           # 产品表定义
│   ├── TransferFund.dtf     # 转账事务
│   └── PurchaseGoods.dtf    # 购买商品事务
├── testdb/                  # 测试数据库
│   ├── User.st              # 测试用户表
│   └── TestTransaction.dtf  # 测试事务
└── defaultdb/               # 默认单文件数据库
    └── User.st              # 默认用户表
```

## 4. 核心设计原则

### 4.1 清晰的层级结构
- 一级目录对应数据库实例
- 二级目录包含表定义和事务逻辑
- 文件类型通过后缀明确区分

### 4.2 灵活的配置机制
- 支持显式配置文件
- 支持默认配置（单文件SQL数据库）
- 支持多种配置格式（JSON、YAML等）

### 4.3 分离的关注点
- 表结构与事务逻辑分离
- 配置信息与业务逻辑分离
- 便于维护和扩展

### 4.4 直观的命名规则
- 数据库名对应文件夹名
- 表名对应.st文件名
- 事务名对应.dtf文件名

## 5. 优势总结

1. **结构清晰**：目录层级分明，便于理解和维护
2. **灵活性高**：支持多种数据库类型和配置方式
3. **扩展性强**：易于添加新的数据库、表和事务
4. **可读性好**：文件名直观反映文件内容和用途
5. **标准化设计**：统一的文件命名和目录结构规范

## 6. 使用说明

1. **创建数据库**：在storage目录下创建新文件夹，文件夹名即为数据库名
2. **配置数据库**：可选创建config.json文件配置数据库连接信息
3. **定义表结构**：创建.st文件定义表结构
4. **编写事务逻辑**：创建.dtf文件编写数据库事务
5. **使用数据库**：通过存储引擎自动加载和使用数据库配置、表结构和事务

## 7. 版本演进
